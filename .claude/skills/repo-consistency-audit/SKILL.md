---
name: repo-consistency-audit
description: Find places where this repo contradicts itself — version pins, documented vs actual architecture, config paths pointing at directories that no longer exist, tooling installed but never run. Use periodically and before onboarding someone.
---

Audit the repository for internal contradictions. These matter more than style:
a stale README teaches the wrong architecture to every new reader, human or
otherwise, and a config path pointing at a directory that no longer exists
silently does nothing.

Report findings; fix only what the user asks for.

## 1. Version pins must agree

Compare every place each runtime is declared:

| Runtime | Declared in |
| --- | --- |
| Ruby | `.ruby-version`, `Gemfile` (`ruby` line), `Dockerfile` (`ARG RUBY_VERSION`), CI (`ruby-version:`) |
| Node | `.node-version`, `.nvmrc`, `Dockerfile` (`ARG NODE_VERSION`), CI (`node-version-file:`), `package.json` engines |
| Yarn/bundler | `Dockerfile` (`ARG YARN_VERSION`), `packageManager`, `Gemfile.lock` `BUNDLED WITH` |

```sh
cat .ruby-version .node-version .nvmrc
grep -nE "ruby ['\"]|RUBY_VERSION|NODE_VERSION|YARN_VERSION" Gemfile Dockerfile
grep -nE "ruby-version|node-version" .github/workflows/*.yml
```

A Dockerfile that pins an older runtime than `.ruby-version` builds a production
image on a different interpreter than every test ran on.

## 2. Documented architecture must match the tree

```sh
ls app/
grep -nE "services|app/" README.md
```

The directory listing in `README.md` is generated by `rake docs:generate_yaml`,
which shells out to `tree`. Regenerate it rather than hand-editing. The task
aborts if `tree` is missing — if it ever writes an empty section, that is a bug
to fix, not to accept.

## 3. Config paths must point at directories that exist

Every path in tooling config is a claim about the tree:

```sh
grep -n "add_group\|add_filter" spec/rails_helper.rb   # SimpleCov
grep -nE "Exclude|Include" -A3 .rubocop.yml            # RuboCop
grep -n "autoload_lib\|eager_load_paths" config/application.rb
```

For each path, check the directory exists. A SimpleCov group or RuboCop
`Exclude` naming a directory that was renamed does nothing and hides the fact
that the real directory is unconfigured.

## 4. Installed tooling must actually run

For each gem or package that exists to be run, find where it runs — CI,
`lefthook.yml`, or a documented command. A linter in the Gemfile with no config
file and no CI step is pure cost.

```sh
grep -nE "brakeman|slim_lint|database_consistency|bundle-audit" Gemfile .github/workflows/*.yml lefthook.yml
ls .rubocop.yml .slim-lint.yml .database_consistency.yml
```

Also check the reverse: a CI step invoking something not in the Gemfile, or an
install command that does not match the lockfile in the repo (a `yarn.lock`
project must not install with `npm ci`).

## 5. Declared capability must be exercised

- a test gem with no specs using it
- a generator setting contradicting how tests are actually written
- an ENV var in `.env.sample` that no code reads, or read by code but absent
  from `.env.sample`

```sh
grep -rn "ENV\[" config/ app/ | grep -oE "ENV\[.[A-Z_]+" | sort -u
cat .env.sample
```

## 6. Dead code

A class with no caller and no spec is where contract bugs hide — nothing
executes it, so nothing catches the drift. Search for callers of each object in
`app/operations`, `app/queries`, `app/presenters`; report the orphans.

## Reporting

Group by severity: things that are actively wrong (a build on the wrong
runtime), things that silently do nothing (a stale exclusion), and cosmetic
staleness. Give the file:line and the one-line fix for each.
