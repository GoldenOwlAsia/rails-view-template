# Translations

`i18n-tasks` is not advisory here. `bundle exec i18n-tasks health` runs in CI
(`.github/workflows/ci.yml`), and `spec/i18n_spec.rb` fails the suite on three
things: a missing key, a locale file that is not normalized, and an
interpolation that differs between locales. The unused-keys example is
commented out on purpose — leave it that way rather than "fixing" it.

- `en` is the only locale that exists. `config.i18n.load_path` globs
  `config/locales/**`, but `config/i18n-tasks.yml` reads only three files:
  `en.yml`, `devise.en.yml`, `simple_form.en.yml`, and **writes** only `en.yml`.
  A key added to a file outside that read list is invisible to `i18n-tasks` and
  to the spec.
- After adding or removing a key, run `bundle exec i18n-tasks normalize`. Hand-
  sorted YAML is the usual reason the suite goes red on a change that looked
  purely additive.
- `i18n-tasks` scans `app/` for usages and skips `app/frontend` and
  `app/assets`. A key referenced only from JavaScript reads as unused.
- `ignore_unused` reserves `common.*` for the flash messages `Crudable` still
  hardcodes. Wiring those through I18n is the intended direction; do not delete
  the reservation to make a report cleaner.
- Custom validators route their messages through `I18n.t` rather than a literal
  string — see `PasswordValidator` and `.claude/rules/models-and-migrations.md`.

## Verify

- `bin/rspec spec/i18n_spec.rb`
- `bundle exec i18n-tasks health` — what CI runs
- `bundle exec i18n-tasks missing` / `unused` when either needs explaining
